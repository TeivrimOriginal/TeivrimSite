# Anime DB

Каталог аниме: агрегирует **AniList**, **Kitsu** и **Shikimori** в одну базу
SQLite и отдаёт JSON API и веб-интерфейс с одного origin.

Нативное Android-приложение в `android/` работает поверх этого API.

---

## Что внутри

| | |
|---|---|
| **Сервер** | Rust 2021, Actix-Web 4, SQLite (`rusqlite`, FTS5), `reqwest` + rustls |
| **Фронтенд** | статические HTML/CSS/JS без сборки: mobile-first, тёмная и светлая темы, RU/EN |
| **Данные** | AniList (основа + связи + рекомендации), Kitsu (оценки, персонажи, озвучка, создатели), Shikimori (русские названия и описания) |
| **Аккаунты** | Argon2id, сессии — непрозрачные токены, в БД хранится только SHA-256 |

Зависимостей намеренно мало: `actix-cors`, `actix-files` и пул соединений
заменены собственными реализациями на ~200 строк, чтобы сборка работала
офлайн и без OpenSSL.

---

## Быстрый старт

### Docker

```bash
docker compose up -d
docker compose logs -f
```

Открыть <http://localhost:8082>.

Первый импорт обходит ~20 000 записей из каждого источника и занимает время
(ограничения публичных API — 30 запросов/мин у AniList без client id). API
отвечает сразу тем, что уже загрузилось; прогресс — `/api/sync/status`.

### Локально

```bash
cp .env.example .env      # при необходимости
cargo run --release
```

`rustup` + Rust 1.80+ — единственное требование. Скачивать SQLite или собирать
OpenSSL не нужно.

## Конфигурация

Всё через переменные окружения, полный список с комментариями — в
[`.env.example`](.env.example). Наиболее полезные:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `BIND_ADDR` / `PORT` | `127.0.0.1` / `8082` | в контейнере нужно `0.0.0.0` |
| `DB_PATH` | `data/AnimeData.db` | файл базы |
| `LOADERS_ON_START` | `1` | `0` — только API, импортом занимается другой инстанс |
| `SYNC_INTERVAL_SECS` | `86400` | как часто каталог пересобирается сам; `0` — только по запросу |
| `ANILIST_CLIENT_ID` | — | поднимает лимит AniList с 30 до 90 запросов/мин |
| `KITSU_ENRICH_LIMIT` | `2000` | сколько тайтлов обогащать персонажами (2 запроса на каждый) |
| `SYNC_ADMIN_TOKEN` | — | без него `/api/sync/start` и `/api/sync/abort` отвечают 403 |

### Ускорение импорта

Получите AniList client id и укажите `ANILIST_CLIENT_ID` — это ускоряет самую
длинную стадию втрое. Остальные источники ограничений не публикуют, но
злоупотреблять ими не стоит.

## API

Базовый путь `/api`. Ответы — JSON, ошибки имеют единый вид:

```json
{ "error": { "code": "not_found", "message": "Аниме не найдено" } }
```

### Каталог

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/anime` | список с фильтрами и пагинацией |
| `GET` | `/api/anime/{uid}` | полная карточка |
| `GET` | `/api/anime/{uid}/raw` | вся строка БД как есть (отладка) |
| `GET` | `/api/search/suggest?q=` | подсказки по названию |
| `GET` | `/api/filters` | справочники форматов, статусов, сезонов, стран, диапазон лет |
| `GET` | `/api/genres?category=genre` | жанры с русскими названиями и количеством |
| `GET` | `/api/genres/{id}/anime` | аниме по жанру |
| `GET` | `/api/stats` | счётчики каталога |
| `GET` | `/api/sync/status` | состояние импорта (публично) |
| `GET` | `/api/img?u=` | прокси обложек с кэшем и allow-list хостов |

#### Параметры `/api/anime`

`page`, `per_page` (до `MAX_PER_PAGE`), `q`, `sort`, `format`, `status`,
`season`, `season_year`, `genre`, `tag`, `studio`, `country`,
`year` / `year_from` / `year_to`, `score_from` / `score_to`,
`duration_from` / `duration_to`, `episodes_from` / `episodes_to`,
`adult` (`no` / `only`), `has_ru`, `has_trailer`, `in_list`.

`sort`: `popularity` (по умолчанию), `score`, `score_asc`, `rating_count`,
`favourites`, `trending`, `year`, `year_asc`, `title`, `title_desc`,
`title_ru`, `episodes`, `duration`, `added`, `updated`, `id`, `id_desc`.

Ответ:

```json
{
  "items": [ { "uid": "al:16498", "title": "Атака титанов", "…": "…" } ],
  "page": 1, "per_page": 48, "total": 21345,
  "total_pages": 445, "has_more": true
}
```

Заголовок `x-total-count` дублирует `total` — удобно отдавать в
`X-...` для клиента, который читает только заголовки.

#### Идентификаторы

`uid` — строка с префиксом источника: `al:16498` (AniList), `ks:12` (Kitsu),
`sh:34` (только Shikimori).

Причина: в версии 1 первичным ключом был `anilist_id INTEGER`, а записи,
отсутствующие в AniList, кодировались отрицательным id из того же диапазона.
MAL-запись 21 и Shikimori-запись 21 схлопывались в одну, а `INSERT OR IGNORE`
молча терял данные. Раздельные пространства имён эту проблему устраняют.

### Аккаунты

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/auth/register` | `{ username, email?, password }` → токен |
| `POST` | `/api/auth/login` | `{ login, password }` → токен |
| `POST` | `/api/auth/logout` | удалить текущую сессию |
| `GET` | `/api/auth/me` | текущий пользователь |

Токен: `Authorization: Bearer <token>`, действителен 90 дней.
Пароли — Argon2id со случайной солью на каждый пароль. Регистрация и вход
ограничены по IP (5 и 10 попыток за 10 минут).

### Список

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/favorites?status=&favorites=&limit=&offset=` | записи вместе с данными аниме |
| `GET` | `/api/favorites/counts` | счётчики по статусам |
| `POST` | `/api/favorites` | создать/обновить `{ uid, status, is_favorite, score, progress, notes }` |
| `PATCH` | `/api/favorites/{uid}` | то же частично |
| `DELETE` | `/api/favorites/{uid}` | удалить |

`status`: `watching`, `planned`, `completed`, `dropped`.
`is_favorite` — отдельная «звезда», не то же самое, что статус: «запланировано
и любимое» — обычное сочетание.

В `POST`/`PATCH` поле, которое не передано, **не меняется**; переданный `null`
очищает значение.

### Синхронизация

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/sync/status` | прогресс (публично) |
| `POST` | `/api/sync/start` | запустить/продолжить импорт |
| `POST` | `/api/sync/abort` | остановить после текущей страницы |

Оба `POST` требуют заголовок `X-Admin-Token` (или `Authorization: Bearer`),
если `SYNC_ADMIN_TOKEN` задан. Если переменная не задана, оба отвечают `403`.

## Как устроен импорт

```
AniList  ──►  строки al:*  (названия, оценки, связи, рекомендации, теги)
   │
Kitsu    ──►  через mappings присоединяется к al:* либо создаёт ks:*
   │         (оценка 0..100, персонажи, озвучка, создатели)
   │
Shikimori──►  по нормализованному названию присоединяется к al:*/ks:*
             либо создаёт sh:*  (русское название, описание, жанры)
   │
   ├──► жанры: строки в genres + связи anime_genres
   └──► пересборка индекса FTS5
```

Каждая стадия пишет чекпоинт в `sync_state`, поэтому прерванный импорт
продолжается с места остановки. Порядок стадий — это зависимость, а не
предпочтение: AniList задаёт множество строк, Kitsu присоединяется к нему по
внешним id, Shikimori — по названию.

Версия 1 запускала часть загрузчиков по `sleep(30)` и `sleep(120)` от старта
процесса. Это была гонка: на медленном прогреве сопоставление жанров видело
недозаполненную таблицу, а сами паузы были ничем не обоснованы. Сейчас
стадии идут последовательно через `await`.

## Поиск

FTS5 с токенизатором `unicode61`. Он приводит регистр для **всех** алфавитов,
поэтому `АТАКА` находит `Атака`. Штатный `LIKE` в SQLite складывает регистр
только для ASCII — в версии 1 русский поиск не работал вообще.

Если SQLite собран без FTS5 (не наш случай, но возможно), индекс не
создаётся, в лог пишется предупреждение, а поиск переключается на `LIKE`-сканы.
Работоспособность сохраняется, но регистр кириллицы учитываться не будет.

## Разработка

```bash
cargo run                       # отладочная сборка и запуск
cargo build --release           # релизная сборка
cargo clippy -- -D warnings     # линтер
cargo fmt --check
pwsh -File tools/make-icons.ps1 # перегенерация иконок
```

Обновление каталога без перезапуска:

```bash
curl -X POST -H "X-Admin-Token: $SYNC_ADMIN_TOKEN" http://localhost:8082/api/sync/start
```

### Структура

```
src/
  main.rs        запуск сервера, маршруты, middleware
  config.rs      конфигурация из окружения
  db/            пул соединений и схема
  sources/       клиенты AniList / Kitsu / Shikimori
  loader/        оркестрация импорта и апсерты
  api/           HTTP-обработчики
  http/          CORS, статика, rate limit, заголовки
frontend/        статический интерфейс (без сборки)
android/         нативное приложение
tools/           генерация иконок, загрузка в RuStore, проверки
```

## Проверки

Всё запускается на Windows PowerShell 5.1 и на PowerShell 7.

```powershell
# Rust: компиляция и предупреждения
cargo clippy --all-targets

# PATCH-семантика списка: поле отсутствует / поле null / значение.
# Нужен запущенный сервер.
powershell -File tools\test-favorites-patch.ps1 -BaseUrl http://127.0.0.1:8100

# Разбор приватного ключа RuStore на настоящем ключе
powershell -File tools\test-rustore-signing.ps1
```

`test-favorites-patch.ps1` регистрирует временного пользователя, пишет запись,
проверяет все три состояния каждого поля и удаляет запись. Он ловит именно тот
класс ошибок, который не виден ни в компиляторе, ни в ответе одного запроса:
«поле не применилось» выглядит как успех.

`test-rustore-signing.ps1` нужен потому, что разбор ASN.1 написан руками ради
совместимости с PowerShell 5.1.
