# Публикация в RuStore

Пошаговая инструкция для `ru.teivrim.anime`.

---

## 1. Сборка подписанного AAB

```bash
cd android

# Один раз: создать ключ подписи
powershell -File ..\tools\make-keystore.ps1

# Сборка
./gradlew :app:bundleRelease
```

Артефакт: `android/app/build/outputs/bundle/release/app-release.aab`

Проверить, что он подписан:

```bash
$ANDROID_HOME\build-tools\36.0.0\apksigner verify --print-certs app-release.aab
```

> Ключ из шага выше **нельзя терять**. RuStore не даёт сменить ключ
> подписи существующего приложения: без него обновление не примут. Храните
> копию отдельно от репозитория.

---

## 2. Регистрация приложения

1. Откройте <https://www.rustore.ru> → войдите под аккаунтом разработчика.
2. **Мои приложения → Создать приложение**.
3. Заполните:
   - **Название**: `Каталог аниме`
   - **Краткое описание** (до 30 символов): `Каталог аниме с RU`
   - **Категория**: `Развлечения` (или `Книги`)
   - **Доступ**: `Все страны` либо `Россия`
4. После создания RuStore выдаст идентификатор приложения. Он нужен только для
   ручной работы в консоли: загрузка через RuStore Connect адресуется именем
   пакета `ru.teivrim.anime`.

---

## 3. Метаданные

Всё заполняется в консоли RuStore на русском. Тексты ниже — готовые к вставке.

### Краткое описание (до 30 символов)

```
Каталог аниме с RU-названиями
```

### Полное описание (до 4000 символов)

```
Каталог аниме с русскими названиями, оценками, жанрами и описаниями.

Данные собраны из трёх открытых источников: AniList, Kitsu и Shikimori.
Мы не храним видео — приложение ведёт только каталог метаданных.

Что внутри

• Поиск по названию на русском, английском и ромадзи, без учёта регистра
• Фильтры: формат, статус, сезон, жанр, страна, год, диапазон оценки, 18+
• Сортировка по популярности, оценке, числу оценок, тренду, избранному,
  дате выхода, названию и длительности эпизода
• Подробная карточка: описание, синонимы, жанры, теги, студии, персонажи
  с озвучкой, создатели, связанные работы и похожие тайтлы
• Ссылки на легальные стриминг-площадки, если они указаны в источнике
• Свой список: смотрю / запланировано / просмотрено / брошено, оценка,
  прогресс по эпизодам, заметки
• Синхронизация списка между устройствами через аккаунт
• Тёмная и светлая тема, интерфейс на русском и английском

Про анонимность

Регистрация не обязательна: каталог, поиск и фильтры работают без аккаунта.
Аккаунт нужен только чтобы вести свой список. Пароли не хранятся: сервер
держит только Argon2id-хеш.

Данные и права

Каталог агрегирует открытые API AniList, Kitsu и Shikimori. Все права на
названия, описания и изображения принадлежат их правообладателям. Приложение
не распространяет контент и не содержит ссылок на пиратские источники.
```

### Категория и возраст

- Категория: `Развлечения`
- Возрастной рейтинг: `12+` (приложение только каталог; но в описании есть

## 4. Графические материалы

| Что | Требование RuStore | Как сделать |
|---|---|---|
| Иконка | 512×512 PNG | `frontend/static/icon-512.png` (есть) |
| Иконка (adaptive) | слои foreground/background | `android/app/src/main/res/mipmap-anydpi-v26/` |
| Скриншоты телефона | от 2 шт., 1080×1920 или 1440×2560 | снять с эмулятора, см. ниже |
| Скриншоты планшета | по желанию | те же экраны на 7" |

### Иконка

Готовые файлы уже в репозитории:

- `frontend/static/icon-512.png` — 512×512 для консоли RuStore
- `frontend/static/icon-maskable-512.png` — с безопасной зоной под маску
- `android/app/src/main/res/drawable/ic_launcher_*.xml` — векторные слои
- `android/app/src/main/res/mipmap-*/` — обычные PNG для API 24–25, где
  `<adaptive-icon>` ещё не существует

Перегенерировать: `powershell -File tools/make-icons.ps1`

### Скриншоты

Снять с эмулятора Pixel (1440×2560, density 560):

1. Запустить эмулятор и установить приложение:
   ```bash
   cd android && ./gradlew :app:installDebug
   ```
2. Сервер должен быть доступен с машины — либо локальный на порту 8082, либо
   прод. Для эмулятора `10.0.2.2` указывает на хост.
3. Подготовить каталог: дождаться, пока в базе есть хотя бы несколько тысяч
   записей (иначе каталог пуст и скриншоты неинформативны).
4. Снять 4–6 экранов:
   - каталог с сеткой карточек
   - открытые фильтры
   - карточка аниме с обложкой и описанием
   - секция «Персонажи и озвучка»
   - «Мой список» с записями
   - тёмная тема
5. Экспорт: **Device screenshot** в Android Studio, либо
   `adb exec-out screencap -p > shot.png`

Снимать лучше в тёмной теме: она выглядит аккуратнее на скриншотах, а
светлая проверяется отдельно.

## 5. Загрузка через API

Загрузить можно и через консоль, но API удобнее: он же понадобится для
последующих обновлений.

Ключи берутся в консоли RuStore (**Настройки → API-ключи**). Нужны два:

- **Key ID** — публичный идентификатор ключа
- **Приватный ключ** — тело PEM без строк `BEGIN`/`END`

```powershell
$env:RUSTORE_KEY_ID      = "key id из консоли"
$env:RUSTORE_PRIVATE_KEY = "тело приватного ключа"

powershell -File tools\rustore-upload.ps1 `
    -FilePath android\app\build\outputs\bundle\release\app-release.aab
```

Проверить без загрузки — скрипт покажет, что именно уйдёт на сервер:

```powershell
powershell -File tools\rustore-upload.ps1 -FilePath app-release.aab -WhatIf
```

### Как это работает

RuStore Connect — не один запрос, а цепочка:

1. `POST /public/auth` — подпись `keyId + timestamp` алгоритмом RSA-SHA512 даёт
   JWE-токен, который передаётся в заголовке `Public-Token`.
2. `GET /public/v1/application/{pkg}/version?versionStatuses=DRAFT` — поиск
   черновика.
3. `POST /public/v1/application/{pkg}/version` — создание черновика из
   `tools/rustore-app.json`.
4. `POST /public/v1/application/{pkg}/version/{id}/aab` — загрузка бандла.
5. `POST /public/v1/application/{pkg}/version/{id}/commit` — отправка на
   модерацию.

Скрипт выполняет 1–4. Пятый шаг запускается только с `-Commit`: первая загрузка
почти всегда требует правки карточки в консоли, и тратить слот модерации до
этого не стоит.

Если черновик уже есть, по умолчанию он переиспользуется. Варианты:

```powershell
-DraftStrategy reuse_existing     # по умолчанию
-DraftStrategy delete_and_create  # пересоздать
-DraftStrategy fail_if_exists     # упасть, если черновик есть
-VersionId <id>                   # работать с конкретным черновиком
```

`versionCode` в этой схеме не передаётся: он берётся из самого AAB, то есть из
`defaultConfig.versionCode` в `android/app/build.gradle.kts`. RuStore отклоняет
дубликаты, поэтому **увеличивайте его с каждой сборкой**.

Старая схема (`access_token` + подпись в query-строке) RuStore больше не
принимает — скрипт использует текущую.

### Проверка подписи

Приватный ключ разбирается из DER вручную, чтобы скрипт работал и на Windows
PowerShell 5.1, где нет `ImportRSAPrivateKey`. Такое стоит проверять:

```powershell
powershell -File tools\test-rustore-signing.ps1
```

Скрипт собирает настоящий ключ в обоих форматах, прогоняет его через тот же
разборщик и проверяет, что подпись проходит верификацию.

## 6. После загрузки

1. Загрузить метаданные в консоли и отправить на модерацию.
2. Модерация RuStore занимает от 1 до 3 рабочих дней.
3. Возможные причины отказа:
   - **Иконка не соответствует шаблону** — нужен ровно 512×512 PNG без
     посторонних элементов и прозрачности по краям.
   - **Нет скриншотов телефона** — минимум два.
   - **Описание почти совпадает с именем** — добавьте реальный текст.
   - **Заявлены разрешения, которых нет** — в манифесте только `INTERNET` и
     `ACCESS_NETWORK_STATE`, это должно совпадать с ответом в анкете.
   - **Приложение фактически является сайтом в WebView** — здесь это не так:
     нативный Compose UI, обращается к API, офлайн-режима без сети нет.

- [ ] `versionCode` в `app/build.gradle.kts` увеличен
- [ ] AAB собран с `--release` и подписан
- [ ] `apksigner verify` проходит
- [ ] `API_BASE_URL` в релизе указывает на `https://`
- [ ] Приложение открывает каталог на устройстве без debug-флага
- [ ] Скриншоты сняты с актуальной сборки
- [ ] `tools/rustore-app.json` совпадает с тем, что в консоли
- [ ] Описание не содержит обещаний, которых нет в приложении
- [ ] Ссылка на политику конфиденциальности добавлена, если RuStore её потребует
